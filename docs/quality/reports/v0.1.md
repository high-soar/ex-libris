## 3. 原因傾向分析と再発防止 Kaizen アクション

### 3.1 傾向 1: 原因 `D`（設計・例外境界・CI/リリース契約・トレーサビリティ）が 75.9%（44 / 58 件）

- **主な事象**:
  - **上流設計レビューによる境界詰めの高度化（24 件）**: `v0.1` では ZIP64/LFH/64KB 結合境界・見開きずらし計算・`MAX_TEXTURE_SIZE` 分割中断・シェーダー/DB 直列化等の複雑状態設計が増えたことで、Step 2 レビュー段階で詳細境界が精査された。
  - **横断レビューでのリリース／テスト契約・トレーサビリティ漏れ検出**: `release.yml` の品質レポート探索正規表現（`^v0.1-.*\.md$`）が規約 `v0.1.md` と不一致（`R1-20`）、CI 成功確認・SemVer 後退防止ガード欠落（`R1-16`）、`testing.md` 例外規約の明文化漏れ（`R1-13`）、`NFR-01` TTFP・`AC-GL-05`/`AC-RD-15` の IT トレース不足（`R1-08`, `R1-09`）、品質台帳 SHA/分類の表記揺れ（`R1-03`, `R1-05`, `R1-17`）、`related_specs` 双方向リンク欠落（`R1-02`, `R1-22`）。
- **Kaizen 反映（Step 3 適用）**:
  1. **`.github/workflows/release.yml`・`docs/specs/architecture.md`・`scripts/android-build-config.test.ts`**:
     - `reportPattern` を `^v${major}\.${minor}(?:-.*)?\.md$`（`vX.Y.md` 優先）へ修正し、`AC-APK-05` 契約テストを追加（`R1-20`）。
     - `permissions` に `actions: read` / `checks: read` を追加し、既存 `v*.*.*` タグに対する **SemVer 単調増加チェック** および対象 SHA の **`ci.yml`（`Lint, Test & Quality Gates`）成功検証** をリリース前ゲートへ強制（`R1-16`）。
  2. **`docs/guidelines/testing.md`**:
     - `§1.5`（`src/test/**`・`*.worker.ts` 1対1例外）、`§1.6`（純粋 Context Provider 透過例外）、`§1.8`（`null` 返却空状態ストーリー `skip-vrt` 許可）を明文化（`R1-13`）。
     - `§3.3` に `SpreadMode = "auto"` 下での単ページ IT 明示ビューポート（`375×667`）必須化（`R1-15`）および `release.yml` 変更時の契約テスト追加義務（`R1-16`, `R1-20`）を追加。
  3. **`.agents/skills/phase-final-review/SKILL.md`**: Step 3 品質分析時の LOC 規模測定・バグ台帳集計をスクリプトによる機械集計必須と明記し、手数え不一致を再発防止。

### 3.2 傾向 2: Worker / キャッシュ・ライフサイクル境界（製品 6 件：`R1-01, 06, 07, 10, 11, 12`）

- **主な事象**:
  - `Worker` の `error`/`messageerror` 未購読による RPC 永続ハング（`R1-07`）、`*.worker.ts` 内の残存三項演算子（`R1-10`）、80MB 超ページの `subarray` 複製（`R1-11`）、`openEpoch` へ誤結合した初期設定適用ガード（`R1-01`）、`zipIndexCache` 破損時の自己修復欠落（`R1-06`）、`resetTestDb` グローバルフックの環境制限未設定（`R1-12`）。
