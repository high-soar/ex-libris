## 3. 原因傾向分析と再発防止 Kaizen アクション

### 3.1 傾向 1: 非同期競合・状態遷移・一時障害分離（`A`: 13 件 / `S`: 9 件 / 製品 `D`: 10 件）

- **主な事象**:
  - 表紙抽出スケジューラの永続化失敗時の `activeVolumeId` 固着（`R1-02`）、オフライン・5xx 一過性障害での蔵書全体恒久 `error` 汚染（`R1-03`）、`dispose()` 時保留 RPC 未解決（`R1-10`）、`syncQueue()` / `retryFailedCovers()` の例外握りつぶし（`R1-08`）、`decompressSlice` 伸長上限欠落（`R1-11`）、レイヤー逆依存（`R1-09`）。
  - Android 実機特有の挙動：`GoogleAuthPlugin.java` の破棄時 `RejectedExecutionException` / `getContext()` null 参照（`R1-17`）、`AndroidManifest.xml` の `ACCESS_NETWORK_STATE` 未宣言により WebView で `window` `online` イベントが発火しない問題およびバックグラウンド復帰検知欠落（`No. 83`, `No. 85`）。
  - SPA / モーダル境界：順方向スクロール引き継ぎ・`0px` 未復元（`R1-21`）、`useEffect` フォーカス取得と背面 `inert` の競合（`R1-23` / `No. 60`）。
- **Kaizen 反映（`docs/guidelines/testing.md`・`.agents/agents/pr-reviewer.md`）**:
  1. **`testing.md §2.4`**: `HO-11`（`freeSavedCall` → `getBridge().saveCall`/`getSavedCall`/`releaseCall`）を解消し、Android ネイティブプラグインの `RejectedExecutionException` / `getContext()` null ガード、および WebView `online` 検知用の `ACCESS_NETWORK_STATE` 権限＋`visibilitychange` 復帰検証を必須化。
  2. **`testing.md §3.1 / §3.4`**: 一過性障害のバックオフ分離（`pending` 維持）・`try/finally` ロック解除・`dispose()` `AbortError` reject、モーダル `useLayoutEffect` フォーカス捕捉・`fallbackFocusRef`・SPA スクロール制御・`afterEach` `cleanup()` 先行による React `act(...)` 警告ゼロ化・`vi.spyOn` 用 `afterEach(() => vi.restoreAllMocks())` を基準化。
  3. **`.agents/agents/pr-reviewer.md`**: 上記観点を独立 PR レビュー項目へ追加。

### 3.2 傾向 2: 設計・トレーサビリティ・品質台帳正規化（`D`: 54 件 / 63.5%）

- **主な事象**:
  - 上流 Step 2 レビューでの事前封じ込め（20 件）に加え、Step 4 IT PR 自体の記録行における `main` squash SHA 未正規化およびアーカイブ後 `changes/` パス未追随の再発（`R1-05` / `No. 42`）、`db-schema.md` / `google-drive.md` の `related_tests` 同期漏れ（`R1-07`, `R1-19`）、非機能要件 `NFR-01` / `NFR-03` の検証分担・実測記述整理（`R1-01`, `R1-04`）。
- **Kaizen 反映（`docs/guidelines/workflow.md`・`testing.md §6`・`.agents/skills/iterative-github-task-management/SKILL.md`）**:
  1. **`R1-05` プロセス是正**: 「Step 2 設計 PR や Step 4 IT PR 自体のマージ前に台帳へ追記した行およびアーカイブ移動した差分仕様パスは、直後の後続 PR または Milestone Step 2 / Step 3 にて `PR #XX @ <main-squash-sha>` および `docs/specs/changes/archive/...` へ必ず正規化する」ことを正本ガイドラインおよびスキル手順へ明文化。
